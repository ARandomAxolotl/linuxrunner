Experimental LinuxRunner Metal backend: explicit opt-in, Debian ARM64 only.
Limited, non-conformant EGL/GLES1 conventional API dispatch. X11 window and
pbuffer surfaces, matrices, bounded vertex buffers, float/fixed vertex/color
arrays, indexed triangles/fans/strips, directional default light/material,
flat/smooth shading, normalization, depth LESS, back-face CCW culling, clear,
readback, finish. No advertised GL extensions or conformant GL version.

Unmodified Mesa GLES1 gears source uses this backend via gpu-gears.sh's scoped
library selection. System Mesa and normal applications remain unchanged.
GPU rasterization and depth are Metal; vertex transformation and lighting are
currently guest CPU work. Window presentation still uses CPU readback/XPutImage,
then existing X11/RFB transport. BGRA row/channel conversion is host-vectorized.
Draws are batched (maximum64 operations); readback/finish returns GPU failures.
GLES2 subset adds Khronos GLSL ES100 parsing/linking, SPIR-V to MSL,
GPU vertex/fragment shader execution, float/vector/mat4 uniforms, generic
attributes, VBO/EBO drawing, shader/program lifetime, bounded pipeline cache
and resize without context destruction. gpu-gears2.sh selects this provider
only for unchanged Mesa GLES2 gears. Build855 adds sampler2D shaders, four
fragment texture units, 32 bounded texture names, unsigned-byte RGBA/RGB/alpha/
luminance uploads, unpack/pack alignment, subimages, filters/wraps, generated
mipmaps, incomplete-texture behavior, viewport offsets and partial readback.
The GLES2 Textures action executes actual guest pixel assertions in an xterm.
Texture storage is limited to8MiB/context including mip levels; targets remain
at most512x512. Build857 adds RGBA level-zero color-texture framebuffers,
GPU render-to-texture and sampling, attachment lifetime/deletion, completeness,
resize, and bounded storage including retained deleted attachments. Texture
orientation is preserved by GPU blits without CPU readback between these passes.
GLES2 Targets runs pixel and quota assertions. Depth/stencil renderbuffers,
non-RGBA framebuffer attachments, explicit mip-level uploads, Metal GLX,
shared contexts, full GLES/OpenGL conformance, Blender Metal rendering and
GPU acceleration of existing browsers remain unsupported.

Advanced custom launch LINUXRUNNER_GLX=software enables real Xvfb/system Mesa
GLX for diagnostics. This uses llvmpipe, NOT the Metal guest provider. The
normal session remains GLX-disabled; no installed Mesa libraries are replaced.

GPU Bridge Test persists through pointer movement and clicks; Escape/window
close ends it. RFB frame count is NOT GPU render FPS. GPU_EGL_SWAP render_fps
measures guest swaps, not native display refresh. Detailed error/event counters
are bounded; no authentication data is collected.

858 adds an explicit experimental client libGL/GLX provider, GLSL vertex/fragment
shader dispatch and VAOs. It is not a conformant desktop OpenGL implementation
and rejects Blender's OpenGL 4.3 core request. GLX Metal Check performs guest
pixel assertions and reports actual completed Metal rendering. GLX Metal App
runs unchanged Mesa glxheads. System Mesa/llvmpipe remains unchanged.
